Git Init Sampai Push: Alur yang Sering Dilupakan

7 Sep 2026·6 menit baca·Jo

Aku bisa mengetik git add, git commit, git push tanpa berpikir panjang sekarang. Tapi butuh waktu cukup lama sebelum aku benar-benar paham APA yang sebenarnya terjadi di balik ketiga command itu — dan justru itu yang bikin aku sering panik waktu ada error yang tidak familiar.

Tiga area: working directory, staging, repository

Working directory adalah folder tempat kamu benar-benar mengedit file — ini yang kamu lihat di code editor. Staging area (disebut juga "index") adalah tempat perantara: git add memindahkan perubahan dari working directory ke sini, semacam memilih dulu perubahan mana yang mau disertakan sebelum benar-benar disimpan permanen. Repository adalah tempat histori permanen itu tersimpan — git commit mengambil semua yang ada di staging area dan mengubahnya jadi satu snapshot bertanda hash unik di repository.

Kenapa commit message itu penting

Setiap commit menyimpan pesan yang menjelaskan apa dan kenapa perubahan itu dibuat. Ini terasa remeh sampai suatu hari kamu butuh melacak kapan sebuah bug mulai muncul lewat git log — commit dengan pesan "update" atau "fix" tidak memberi petunjuk apa pun, sementara pesan seperti "fix login bug yang mencegah reset password" langsung menunjukkan arah pencarian.

Push: mempublikasikan checkpoint-mu

Semua commit yang dibuat sejauh ini masih hidup di komputer lokal saja. git push adalah langkah yang mengunggah commit-commit itu ke remote repository seperti GitHub, sehingga bisa dilihat dan dikerjakan bersama orang lain. Sebelum push, praktik yang baik adalah git pull dulu untuk menarik perubahan terbaru dari remote — supaya kamu tidak mempublikasikan sesuatu yang sudah "ketinggalan" versi.
